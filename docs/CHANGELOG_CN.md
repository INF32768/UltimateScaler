本次更新标志着[项目重构](https://github.com/INF32768/UltimateScaler/wiki/Project.Refactoring.zh)的完成，以重建项目基础为主，没有新增玩法内容。游戏内行为保持兼容，现有的 V2/V3 配置会自动迁移到新的 V4 格式。

### 新增

- 全新的配置界面：五个分类、统一的环境/风险/性能/重启标签、距离现象图例、按条件显示的子选项、十进制输入校验、
  方块下拉框，以及可点击的 Wiki/Issue 链接。
- 从 V2/V3 配置到 V4 配置模型的自动迁移。
- AppVeyor 夜间构建与正式发布流水线；打 Tag 即可自动构建、打包和发布。
- 项目文档与社区基础设施：重写 README、补充 CONTRIBUTING、建立贡献者名单、提供中英文 Issue 模板、完善 Wiki 页面，
  并为核心代码补充 Javadoc。
- 为随附依赖提供第三方许可证文件。

### 变更

- 配置模型升级为 V4，按常规、世界生成、修复与扩展、实用工具分节，字段名更贴近实际行为。
- 配置迁移结果会立即写回；只有在新的配置成功保存后，才会删除 V2 文件。
- 快捷键现在直接打开新版配置界面。配置在启动时加载，首次启动会生成默认配置文件，`/reload` 会重新读取配置。
- 配置文件头现在链接到 Wiki；详细说明统一放在 Wiki 和界面提示中。
- 迁移到 mojmap 和现代 Fabric 项目模板，包名改为 `xyz.inf32768.ultimatescaler`，并分离客户端与通用代码。
- 统一配置相关命名，新增 `ModMetadata` 集中常用常量，版本比较改用 Fabric 内置的 `Version`。
- 升级到 Gradle 9.5.1、Loom 1.17、Fabric Loader 0.19.3、Fabric API 0.136.1。
- 替换不稳定的 `@ModifyConstant` 注入，提升跨版本兼容性。
- 重写 `locate pos`：参数统一为 `double`，支持负数，不再需要手动指定搜索范围，并显著降低计算耗时。
- 调试屏幕的坐标换算增加缓存，减少重复计算。
- 采用 Conventional Commits、主干开发和原子提交作为项目工作流。

### 弃用

- 旧配置界面保留为过渡入口并标记为弃用；按住 Shift 点击 Mod Menu 中的模组图标仍可进入。它将在后续版本中移除。

### 移除

- 配置文件不再写入逐项注释。
- `locate pos` 中手动指定搜索范围的功能。
- 内置的 toml4j 源码；toml4j 现在作为正式依赖使用。

### 修复

- 修复配置加载在加载或 V3 迁移失败时用默认配置覆盖当前配置的问题。模组现在会保留并写回重载前的配置；如果此前
  没有可用配置，才使用默认值。执行兜底写入前，原文件会备份为 `ultimate_scaler.toml.bak`；保存时先写入临时文件，
  并在文件系统支持时使用原子替换。
- 修复 `RELEASE` 边境之地位置的行为。
- 修复特定配置下末地岛的错误偏移。
- 修复 `WeirdScaledSampler` 的 `rarity` 计算。
- 修复废弃矿井 Mixin 的目标名错误。
- 修复若干 1.21.x 下的编译与运行问题，包括流体采样器相关崩溃和 Mixin 加载条件。

> **升级提示：** 现有的 V2/V3 配置会自动迁移到 V4；如果使用自定义配置，建议升级前备份一份。旧配置界面已弃用，
> 并将在后续版本中移除。

> 自动化冒烟测试仍作为后续工作暂缓；当前保留构建验证。正常功能开发从本版本起恢复。
